**Observations:**

- Spec line 39 ("Then free the previous owner's slot exactly as in `advance`") is
  unreachable through the public API. A successful `transfer` requires the target rep to be
  below capacity (check 6), while a non-empty waiting queue means every rep is at capacity
  (line 18 only queues a lead when no rep qualifies, and every slot-freeing operation drains
  immediately). So the drain after `transfer` can never find a queued lead. Implemented as
  written (`self._free_slot(previous_owner)` is called) and pinned by
  `test_successful_transfer_logs_no_assign` and `test_transfer_is_blocked_while_every_rep_is_full`,
  rather than by a fixture that cannot exist. Same reasoning bounds line 31's `while` loop to
  one assignment per freed slot — pinned by `test_drain_stops_at_capacity_not_through_the_whole_queue`.
- Ordering between two consecutive checks that raise the *same* exception type is not
  observable from outside (e.g. `transfer` checks 3/4/5/6 are all `ValueError`). Where the
  types differ, the order is pinned explicitly: `add_lead` email/name/source/duplicate;
  `qualify` 1-2 and 2-3; `convert` 2-3 and 3-4/3-5; `advance` 2-3, 3-4, 5-6; `discount`
  2-3, 3-4, 4-5, 5-6; `transfer` 1-2.
- The domain rule was read literally as stated: a valid email needs *some* `.` that is
  neither the domain's first nor last character. So `a@co.m.` and `a@corp..` are accepted
  (interior dot exists) while `a@.corp.`, `a@corp.`, `a@.com` and `a@.` are rejected. If the
  Auditor intends "exactly one dot, interior", that is a spec change, not an implementation
  one — the two readings differ only on domains with a trailing dot.
- `forecast` has no `actor` parameter, so the unknown-actor rule does not apply to it;
  confirmed it appends nothing to `log` and mutates nothing.
